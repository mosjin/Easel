# 发布实战经验记录

本页沉淀**真实发布过程中验证过的经验**：平台入口现状、踩坑与可复用的操作路径。
与 [known-issues.md](./known-issues.md)（Easel 自身使用问题）区分——这里记的是「平台侧怎么走通」。

> 记录原则：只写实际核查过的事实，标注核查方式；平台改版频繁，入口结论请连同日期一起看。

## 一、各平台「原创标识」现状（核查日期 2026-10-13）

投稿时或发布后想给内容打「原创」标，各平台能力差异很大。实测结论：

| 平台 | 是否可标原创 | 入口 / 说明 | 核查方式 |
|------|--------------|-------------|----------|
| 小红书 | ✅ 有「原创声明」 | 笔记编辑页 → 打开「原创声明」开关 → 弹《原创声明须知》→ 勾选同意 → 点「声明原创」→ 发布保存 | 编辑页回读开关状态 |
| B站 | ✅ 投稿类型即「自制(原创)」 | 投稿参数 `--copyright 1`（biliup 默认值）；`2` 为转载 | member 稿件 API 回读 `copyright` |
| 微信视频号 | ✅ 有 | 发布页可选 | 用户确认 |
| 微信公众号 | ✅ 有 | 发布时可选原创声明 | 用户确认 |
| 抖音 | ⛔ 无「原创」项 | 编辑页只有「自主声明」：内容由AI生成 / 内容为个人观点或见解 / 内容为转载信息 / 内容含营销推广信息 / 虚构演绎仅供娱乐 / 无需添加自主声明 | 编辑页展开下拉逐项核对 |
| 快手 | ⛔ web 端无入口 | 创作服务平台的发布页与作品管理页都没有原创声明；官方发布流程也未包含该步骤（通常仅 APP 端可选） | 发布页/管理页全文检索 + 发布流程复盘 |
| 知乎 | ⛔ 无「原创」项 | 编辑页只有「内容类型声明」：包含剧透 / 医疗建议 / 虚构创作 / 理财内容 / AI 辅助创作 / 无声明 | 编辑页展开下拉逐项核对 |

**注意**：抖音的「自主声明」里最接近的是「内容由AI生成」，属**反向**合规披露，不要误勾成原创。

**另注**：已发布作品想补标原创，前提是平台提供「编辑已发作品」入口。
- 抖音：作品管理 → 编辑作品（有次数上限，页面提示「每个作品最多修改 5 次」）。
- 快手：web 端作品管理未提供编辑入口，故已发布内容无法回补。
- 小红书：笔记管理 → 编辑，可回到发布器修改。

## 二、知乎专栏正文：必须走「富文本粘贴」

**症状**：用脚本发布/更新知乎文章后，正文把 `### 一、…`、`**加粗**` 这类 Markdown 标记**原样显示**成文字，没有转成标题和加粗。

**根因**：知乎专栏正文是 **Draft.js** 富文本编辑器。粘贴 `text/plain` 时 Draft.js 不会解析 Markdown，只会把源码当纯文本插入；而粘贴 `text/html` 会按 HTML 结构正常转换（标题/加粗/有序列表/引用都能识别）。

**修复**：`skills/shared/scripts/web_publisher.py` 新增 `paste_md` 动作——
把 Markdown 转成 HTML（`_md_to_html`）后连同纯文本兜底一起写入剪贴板 `DataTransfer`，再向当前可编辑元素派发 `paste` 事件；知乎发布流程的正文步骤由 `type` 改为 `paste_md`。

**已验证**：转换后 DOM 富文本计数 H3×5 / 有序列表×2 / 引用×1 / 加粗×11，残留 Markdown 标记 0。

> 修已发布文章同理：进 `/p/<id>/edit` → 全选正文 → 粘贴 HTML 富文本 → 校验 DOM → 点「更新」。

## 三、小红书「原创声明」操作路径（含两个坑）

完整路径（编辑已发布笔记）：

1. 打开 `creator.xiaohongshu.com/publish/update?id=<note_id>&noteType=normal`
2. 打开 `.original-wrapper` 下的「原创声明」开关
3. 会弹出《原创声明须知》弹窗（`.d-modal.d-modal-centered`）：先勾选「我已阅读并同意」，**否则「声明原创」按钮是 disabled 状态**
4. 点「声明原创」→ 开关置为开
5. 点发布保存

**坑 1：发布按钮在闭合 Shadow DOM 里。**
编辑页的提交按钮是自定义元素 `<xhs-publish-btn>`（shadow root 为 closed，`querySelectorAll('button')` 看不到它）。要按 host 的包围盒点击：**发布按钮在 host 水平约 50% 处**（实测品牌红像素落在 host 宽度的 41%–59%），点 host 中心即可；单纯 `element.click()` 或点错比例会落在按钮外，什么都不会发生（页面不跳转、无 toast，容易误判成成功）。

**坑 2：弹窗遮罩会吃掉点击。**
原创声明须知弹窗未关闭时，遮罩 `d-modal-mask` 会拦截后续点击——必须先勾选同意并关掉弹窗，再点发布。

**判断是否真的保存成功**：更新页保存成功后 URL 会离开 `/publish/update`（跳回笔记管理页）；仅凭「点了按钮」不能算成功，要回读编辑页确认开关仍为开。

## 四、封面/落版署名按平台区分

同一条内容分发到多平台时，**封面落版署名要用该平台对应的账号名**，不要跨平台套用同一个名字（曾有封面沿用了另一个平台的账号名而返工重渲染）。
渲染封面时把占位名替换为该平台账号名后再出图，并在放行前 OCR 抽检一次落款。

## 五、发布前先列资源清单（硬约定）

自动化发布时，**先把本批要上线的资源列成清单给用户过目，确认后再执行**。

- 原因：脚本一旦跑起来，各平台的成片版本、封面画幅、标题文案就直接生效，用户没有「临门一脚」的核对机会。
- 清单至少写清：平台 → 成片文件（时长/画幅）→ 封面文件 → 标题 → 话题/标签 → 署名。
- 多版成片并存时（例如 30s 短版 / 47s 长版），必须写明**哪个平台用哪一版**，避免发错版本。

## 六、成片首帧即封面（避免平台抓错缩略图）

多数平台（抖音 / 快手 / 视频号 / B站 等）**抓视频首帧当封面**，脚本发布时没有单独上传封面的机会。

- 做法：把封面图**覆盖在成片开头约 0.1 秒**，随后立刻回到正片；**不插入新帧、不延长时长、不动音轨、不改字幕时间轴**。
- 校验：抽首帧与封面比对（平均像素差应很小），再抽封面结束后一帧确认已回到正片，并比对修改前后的时长与音轨。
- 工具：`skills/shared/scripts/cover_head.py`（`add` / `check` / `off` / `selftest`）。用户明确要求「不加封面」时跳过此步。

## 七、微信公众号「原创声明」目前无法自动化（2026-10-16 实测）

目标：在 `skill-wechat-publisher` 建好草稿后，自动把文章声明的原创打上（全局规则「能原创的都原创」）。

**结论：做不到，改为人工一点。** mp 编辑器（`appmsg_edit_v2&appmsgid=<id>`）里确有原创开关：

- 开关节点：`#js_original .js_original_apply`（`未声明 / 已声明` 两态，`#js_original_open` 为已声明块）。
- 点开关弹出的声明弹窗含：`声明类型`（`文字原创` 默认选中 / `无需声明`）、`作者`、`白名单`、`快捷转载`、`我已阅读并同意《…协议》`、`确定 / 取消`。
- 但 Playwright 里完成「勾协议 → 点确定」后，**声明不生效**：`body` 里 `已声明` 仍为 False，草稿卡片 `window.wx.cgiData` 中 `"copyright_type": 0`。headless 与 headed（有 X display）均复现；`确定` 有时甚至不关弹窗。
- 编辑器首屏的运营引导浮层（`.education-dialog` / `.weui-desktop-dialog__wrp`「支持添加话题卡片|我知道了」）会拦截点击，需先移除。

**回读校验法**：草稿箱列表页（`t=media/appmsg_list&type=10&action=list_card`，或点左栏「草稿箱」）的内联脚本 `window.wx.cgiData` 里每篇带 `copyright_type`（0=未声明）。比 UI 文案可靠。

**落地**：`publish.py` 与发布流程不做原创声明，**群发前在编辑器人工点一次「原创」→ 勾协议 → 确定**。发布清单里按此项记「待手动」。

**补充（2026-10-16 实战：知乎发「双11 AI 算账」）**：

- **运行时根的 `web_publisher.py` 可能是旧版**：`/home/jin/works/Easel`（停在 `main`）的 zhihu 正文步当初还是 `{"action":"type"}`，会**把 `**`/`###` 原样打出**；带 `paste_md` 的版本只在 `easel_me` main。发布前先 `grep -c paste_md <运行时根>/skills/shared/scripts/web_publisher.py`，为 0 就从 `easel_me` 同步该文件再发（本轮实测：同步后发布成功）。
- **粘贴的 `<strong>` 可能被丢**：`paste_md` 能把 Markdown 转成段落（实测 21 段、0 处 `**`/`#` 残留），但整行加粗的小标题**不一定保留**（截图/回读都看不到 `<strong>`）。补法：编辑页**三击**选中该行 → `Ctrl+B`（编辑器内 `<span style="font-weight:bold">`）或点工具栏 `button[aria-label='加粗']`；**点「更新」必须用真实点击**（Playwright `locator.click()`），用 JS `.click()` 会**丢最后一次格式改动**（实测反复只丢同一段）。
- **回读判据**：公开页 `h1` 标题 + `strong/b` 文本列表 + `p` 段数 + `**`/`^#` 残留数；作者端编辑页 `[data-block=true]` 里 `span[style*="font-weight"]` 判加粗（Draft.js 用内联 style，不是 `<strong>`）。
